# Data provenance

The deployed dashboard is built only from the cleaned BBMED source workbooks in `source-data/`.

The production model uses the following relationship backbone:

- `mes_production_orders.OrderNumber` → `mes_production_periods.OrderNo`
- `mes_production_periods.WorkRecordID` → `mes_stoppages.work_record_id`
- `mes_production_periods.WorkRecordID` → `mes_person_x_work_record.WorkRecordId`
- `mes_production_periods.WorkRecordID` → `mes_rejections_ids_x_work_ids.WorkRecordId`
- `mes_production_orders.ArticleNo` → `erp_product_info.ItemCode`
- manual Excel `Auftragskarte Nr.` → MES order number **after** aggregating manual rows to order grain
- energy reader asset tag → meter/component mapping
- energy/order relationship is time-window allocation; raw cumulative meter readings are **not** directly joined to orders

`data/dashboard.json` is generated by `scripts/build_dashboard_data.py`. It contains the compact order-level dataset and aggregates needed for the browser dashboard. The original workbooks remain the audit source.

The physical unit of `Total Energy Passed` is unspecified in the supplied workbook. Therefore the dashboard reports raw meter units and does not assert kWh or energy cost.

File integrity hashes are in `source-data/SHA256SUMS.txt`.
